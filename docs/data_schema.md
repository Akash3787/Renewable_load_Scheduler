# Data Schema Documentation

The system uses SQLite for offline-first, local persistence. All tables are defined in [`schema.sql`](file:///Users/akashbaskaran/.gemini/antigravity-ide/scratch/renewable_load_scheduler/schema.sql).

## Entity-Relationship Summary

### 1. `generation_forecast`
Stores hourly forecast vintages from API, cache, or climatology fallback.
- `forecast_run_time` (TEXT, PK): Timestamp when forecast execution occurred.
- `target_timestamp` (TEXT, PK): The future hour being forecast.
- `pv_kw_p50`, `pv_kw_p10`, `pv_kw_p90` (REAL): Median and confidence bounds for PV generation.
- `wind_kw_p50`, `wind_kw_p10`, `wind_kw_p90` (REAL): Median and confidence bounds for wind generation.
- `source` (TEXT): Provenance tag (`live_api` | `cache` | `climatology_fallback`).

### 2. `generation_actual`
Ground truth generation data used exclusively during backtesting.
- `timestamp` (TEXT, PK): Hourly timestamp.
- `pv_kw_actual` (REAL): Realized solar output (kW).
- `wind_kw_actual` (REAL): Realized wind output (kW).

### 3. `loads`
Facility equipment profiles and operational constraints.
- `load_id` (TEXT, PK): Unique load key (e.g. `FLEX_OVEN_1`).
- `load_type` (TEXT): `fixed` | `flexible` | `curtailable`.
- `power_kw` (REAL): Nominal operating electrical power.
- `duration_min` (INTEGER): Total required operating minutes within window.
- `earliest_start`, `deadline` (TEXT): Operating window bounds.
- `comfort_band_kw` (REAL): Maximum allowed curtailment for curtailable loads.

### 4. `storage_state`
BESS physical specifications and state tracking.
- `soc_kwh` (REAL): Current energy stored.
- `capacity_kwh` (REAL): Battery energy capacity.
- `max_charge_kw`, `max_discharge_kw` (REAL): C-rate power limits.
- `round_trip_eff` (REAL): Round-trip conversion efficiency.

### 5. `tariff`
Commercial electricity rates.
- `energy_rate` (REAL): Volumetric rate per kWh.
- `demand_charge_rate` (REAL): Peak power tariff rate per kW.
- `is_peak_window` (INTEGER): 1 if peak tariff active, 0 otherwise.

### 6. `schedule`
Execution plan generated by scheduler (Baseline or MILP Optimizer).
- `run_id` (TEXT): Identifier for schedule run.
- `load_id` (TEXT): Target load.
- `scheduled_start`, `scheduled_end` (TEXT): Assigned time slot.
- `power_kw` (REAL): Operating power assigned.
- `power_source` (TEXT): `grid` | `pv` | `wind` | `battery` | `mixed`.

### 7. `field_log`
Local capture of field engineer events, complaints, and overrides.
- `timestamp` (TEXT), `engineer_id` (TEXT), `load_id` (TEXT), `event_type` (TEXT), `note` (TEXT).
